# 修改记录：识别质量（副标题 / 作者臆造 / 切块默认 / 书架号按行统一）

> 记录时间：2026-09-15 ｜ 范围：`book_finder_v3`
> 一句话：针对「作者胡编乱造、副标题漏提」的实测问题，以及交互上「大图切块默认开启」「表格无作者列」「书架号未按行统一」几处，做了代码修改并用真实 API 图片验证。

---

## 1. 问题缘起（有实测证据）

- **作者胡编乱造**：AI 书架整图切块识别（tiles=1，73 块）产出 12 本结果作者**全部填成「王X」**（王伟/王雪/王坚/王万森…）。原因是书脊上作者小字看不清，模型**凭书名联想、靠训练记忆背出作者**。
- **副标题漏提**：同一书架上「人工智能安全」应带副标题「原理剖析于实践」，模型只输出主书名「人工智能安全」。此前提示词虽然要求合并副标题，但**在运行中的旧进程里不生效**，且对某些图（如 AI 书架整图）确实漏。
- **过程排查**：对比最近 12 份 `results/*/result.json` 发现规律——55 书架结果含副标题连接符（——/：），AI 书架结果连接符数=0；进一步核对日志 `识别完成 rid=... tiles=1 整图=0 切块=73`，确认副标题缺失主因是**运行中的服务仍加载旧 PROMPT**（未重启）。用同一张 AI 书架原图跑**新提示词·整图**后，副标题（人工智能安全 原理与实践、行业智能化架构与实践 制造和农业、大模型时代 人工智能的哲学思考…）全部提出，作者全部留空。

## 2. 本轮代码修改

### 2.1 AI 提示词（`apps/server/core/vision.py` `PROMPT`）

针对 `title` 与 `author` 两个字段重写：

1. **副标题必须并入主书名**：
   - 说明副标题常见连接符（`——` `-` `：` `·`）或排成一行较小的字；
   - 只要书脊上印有副标题就必须一并读入 `title`，主书名+副标题合并成一条；
   - 给了具体例子：主书名「沟通错位」+ 副标题「皆大欢喜的谈判妙招」→ 输出「沟通错位——皆大欢喜的谈判妙招」。

2. **禁止臆造作者**：
   - 作者只许读书脊上印刷的名字，去掉「著」「著者」「◎著」「主编」「编」「绘」「译」等字；
   - 字太小/模糊/反光/被遮/根本没印 → `author` 填空字符串；
   - 明确「严格禁止凭书名联想、靠印象背出作者，宁可留空也绝不编造作者名」。

3. **看不清放大仔细辨认**（通用）：看不清的字不要臆猜，自行放大、仔细辨认，实在看不清才留空，宁可少认不要编造。

> 注：原计划文档第 5 节「红线」写过"不要动 vision.py 提示词结构"，本轮因作者臆造+副标题漏提，属于 P-A/P-C 范畴的功能性修正，居间对 PROMPT 做了字段局部重写（未动字段集与 JSON 格式约定）。

### 2.2 大图切块改为非默认

- 前端（`apps/web/src/components/UploadZone.tsx`）：`useState(true)` → `useState(false)`，并加注释「整图识别通常已足够，切块仅在整图结果不准（漏书）时人工开启」；复选框文案改为「（整图不准时再开）」。
- 后端（`apps/server/main.py` `api_recognize`）：`tiles: str = Form("1")` → `Form("0")`，兜底默认整图。

### 2.3 表格增加「作者」列

- `apps/web/src/lib/api.ts`：`Book` 接口新增 `author?: string`。
- `apps/web/src/components/BookTable.tsx`：在「书名」与「置信度」之间新增「作者」列，展示 `book.author`，无作者显示「—」。

### 2.4 书架号按行统一合并、一张图两排不混

- 新增 `apps/server/core/refine.py::assign_shelf_per_row(books)`：
  - 按行（y 带）把**每排书**的书架号统一为该行多数投票聚合后的完整架标；
  - 解决同一架标被不同切块读碎（只读到分类号 `C912.22/44422` 或只读到类目名「社会团体」）导致逐本碎片化；
  - **一张图里两排不同架标时，各行独立聚合、互不混淆**；行内没有架标读数的书保持原值。
- `apps/server/main.py`：管线在 `snap_rows()` 之后、整图级 `majority_shelf()` 之前调用 `assign_shelf_per_row(books)`，并更新注释。

### 2.5 测试与构建

- `apps/server/tests/test_crop.py`：`test_crop_reduces_tiles` 原依赖默认切块开启，改为**显式传 `tiles="1"`**（因为默认已改为关闭），并小范围整理后端调用返回。
- 验证：后端单测 **163 passed**（含上轮行去重用例）；前端 `pnpm build` 成功（`apps/web/dist/` 已更新）。

## 3. 真实 API 图片验证（本次的关键证据）

用**新提示词**直接对已存图片调用视觉接口（`call_vision` → `parse_books`）：

1. **55 书架整图**（`tests/dataset/微信图片_20260914111646_55_155.jpg`）：38 本。
   - 副标题稳定提出：目的经济——社团组织发展新格局、群落化生存——移动互联时代的网络社群生态与传播、高效务实——非营利组织项目管理指南、谈判技巧——如何掌握谈判的主动权、关系何以强弱——批判格兰诺维特、云交往——数字时代的交往与文化…
   - 作者臆造收敛：38 本仅 10 本有作者（路人甲/高永、社交三力/刘艳、关系何以强弱/刘军、洞察社交/刘军、云交往/王敏芝…），均为书脊真印；看不清的留空。
2. **AI 书架整图**（`results/20260915_164532_378/image.jpg`）：82 条（此为该图整图单遍原始输出、未走去重，条数虚高属正常；仅用于看副标题/作者行为）。
   - 副标题现在提出：人工智能安全 原理与实践、行业智能化架构与实践 制造和农业、大模型时代 人工智能的哲学思考、AI 时代 人工智能的伦理与治理、人工智能与科学发现 一种哲学分析…
   - 作者全部留空（臆造已消除）。

> 结论：副标题漏提 + 作者臆造两个问题的根因是**模型行为**，修正提示词后本地整图直调即改善；运行中的服务因未重启仍用旧 PROMPT，故见效前**必须重启**。

## 4. 生效条件与后续注意

- **必须重启服务**生效：关掉当前运行中的 `main.py`（进程里 PID 9312，启动时加载旧 PROMPT），重新双击 `启动图书查找V3.bat`（走 `gen_env.py` 注入密钥 → 8080 起服务）。重启可先确认无残留进程：`Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Where-Object {$_.CommandLine -match 'main.py'}`。
- 重启后若仍有**极个别图**漏副标题，那属于该图分辨率/裁切问题，可再针对那张图微调；但先从整图、新提示词起步。
- 前端产物已 build 到 `apps/web/dist/`，浏览器刷新即可看到「作者」列；`启动图书查找V3.bat` 每次启动会先 `pnpm build`，无需手动处理。
