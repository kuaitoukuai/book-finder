# 微信扫码登录

> 迁移自 AI消息源 v7.1（`AI消息源/ai-review-site-v7.1`），适配本项目 Bearer token 体系。
> 后端实现：`apps/server/core/scan_login.py` + `apps/server/main.py` 中的 4 个路由；
> 小程序端：`apps/miniprogram/pages/wechat-login/`；网页端：`apps/web/src/components/WechatQrLogin.tsx`。

## 功能概述

用户在电脑网页端点「微信扫码登录」→ 展示小程序码 → 用微信扫码进入小程序确认页 →
手机上点确认（静默完成，无需任何按钮）→ 网页轮询命中后自动登录进入。

小程序确认页只做「证明你是这个微信账号」，真正的登录发生在电脑浏览器上，
**token 由网页轮询领取，小程序不接收也不需要 token**。

## 完整时序

```
网页端                后端                       微信服务器            小程序
  │  POST /qr          │                           │                  │
  │───────────────────>│ 生成 ticket(32位hex)      │                  │
  │                    │ 调 getwxacodeunlimit ────>│                  │
  │<── {ticket, qr_image, expires_in}              │                  │
  │ 展示小程序码        │                           │                  │
  │                    │                           │<── 用户扫码       │
  │                    │                           │   (scene=ticket)  │
  │                    │                           │                  │ onLoad 解析 scene
  │                    │                           │                  │ wx.login() 拿 code
  │                    │<── POST /confirm {ticket, code} ────────────│
  │                    │ 调 jscode2session ───────>│                  │
  │                    │<── openid                  │                  │
  │                    │ 按 openid 找/建用户        │                  │
  │                    │ ticket → confirmed        │                  │
  │  每 1.8s 轮询       │                           │                  │
  │  GET /qr/status ──>│                           │                  │
  │<── {status: pending}（若干次）                  │                  │
  │  GET /qr/status ──>│ confirmed → consumed      │                  │
  │                    │ 用 make_token 签发         │                  │
  │<── {status: confirmed, token, username}         │                  │
  │ 存 token，登录完成  │                           │                  │
```

## API 接口

四个接口均**不需要认证**，均带 IP 限流（与 `/api/login` 同款的滑动窗口限流，
窗口 60 秒，超出返回 429 `{"detail": "请求过于频繁，请稍后再试"}`）。

### POST /api/auth/wechat/qr
生成扫码登录票据 + 小程序码。限流：60 次/分钟/IP。

响应 200：
```json
{"ticket": "0c32d0d3...", "qr_image": "data:image/png;base64,...", "expires_in": 300}
```
- `ticket`：32 位小写 hex（16 字节随机），同时作为小程序码的 scene 参数
- `qr_image`：data URL，可直接放进 `<img src>`；真实模式为 PNG，MOCK 模式为 SVG 占位图
- `expires_in`：票据有效期（秒），固定 300

错误：
- 503 `{"detail": "微信登录未配置"}`：未配置 `WECHAT_APPID`/`WECHAT_SECRET` 且未开 MOCK
- 502 `{"detail": "生成小程序码失败，请稍后重试"}`：微信接口异常

### GET /api/auth/wechat/qr/status?ticket=xxx
网页端轮询扫码状态。限流：120 次/分钟/IP（轮询接口，阈值放宽）。

响应 200：
| status | 含义 | 附加字段 |
|---|---|---|
| `pending` | 等待扫码/确认 | 无 |
| `confirmed` | 已确认，token 已签发（票据同时被消费，**仅一次有效**） | `token`、`username` |
| `cancelled` | 用户在小程序里点了「不是我操作的」 | 无 |
| `expired` | 票据过期 / 不存在 / 已被消费 | 无 |

confirmed 响应示例：
```json
{"status": "confirmed", "username": "wx_abc12345", "token": "..."}
```

注意：**刻意不区分「票不存在」「已过期」「已被消费」**，一律回 `expired`，
否则这个接口就成了「某张票是否存在」的探针。命中 confirmed 时用带状态条件的
UPDATE 抢占式消费（`UPDATE ... WHERE status='confirmed'`），两个标签页同时轮询
同一张票只有一个能拿到 token。

错误：400 `{"detail": "票据格式不正确"}`（ticket 非 32 位小写 hex）。

### POST /api/auth/wechat/confirm
小程序端确认登录。限流：60 次/分钟/IP。

请求 JSON：`{"ticket": "...", "code": "..."}`（code 为 `wx.login()` 返回的 js_code）

处理：校验 ticket 格式与有效期 → `jscode2session` 换 openid → 按 openid 找用户，
不存在则创建无密码用户（`wx_` + openid 前 8 位）→ 票据置 confirmed 并写入 username。
**不返回 token**（token 由网页轮询领取）。

响应 200：`{"ok": true, "username": "..."}`

错误：
- 400：票据格式不正确 / 缺少 code
- 401：`{"detail": "微信登录失败: <errmsg>"}`（js_code 一次性有效，40163=已使用，不可重试）
- 404 `{"detail": "二维码已过期，请在电脑上刷新后重新扫码"}`：票据不存在或已过期
- 409：`{"detail": "该二维码已使用..."}`（已被确认/消费）或 `{"detail": "该二维码已被取消..."}`
- 502：微信登录接口不可达 / 返回异常
- 503：微信登录未配置

并发双扫防护：置 confirmed 用带状态条件的 UPDATE
（`WHERE status IN ('pending','scanned')`），只有先到的请求能改成功，后到的拿 409。

### POST /api/auth/wechat/cancel
小程序端「不是我操作的」作废票据。限流：60 次/分钟/IP。

请求 JSON：`{"ticket": "..."}`
响应 200：`{"ok": true}`（无论票据是否存在都返回 ok——取消失败不影响安全，
票据到期后自然作废）
错误：400 票据格式不正确。

## 票据状态机

存储：`data/app.db` 的 `login_tickets` 表（ticket 主键 / status / openid / username /
created_at / expires_at），启动时由 `core/scan_login.py` 的 `init_db()` 自动建表。

```
                 ┌──────────┐
                 │ pending  │ ← create_ticket()（POST /qr）
                 └────┬─────┘
        小程序 confirm │（带状态条件 UPDATE，防并发双扫）
                      ▼
        ┌─── confirmed ───┐
        │  网页轮询命中      │ 抢占式消费（confirmed→consumed，仅一次）
        ▼                 ▼
   consumed         cancelled ← 小程序 cancel（仅 pending/scanned 可取消）
   （终态）          （终态）
```

- **过期**：5 分钟（`TICKET_TTL = 5 * 60`），过期的票在轮询/确认时一律按 `expired` 处理；
  每次生成新票时顺手 DELETE 清理过期票据。
- **一次性**：confirmed 的票被第一次轮询命中即转 consumed，token 只发一次。
- `scanned` 为预留中间态（当前实现 confirm 一步置 confirmed，未使用两步转换）。
- 防 QRLJacking 依赖用户可见性：小程序确认页显示站点名并提供取消入口，
  ticket 印在二维码上不是秘密，但 5 分钟 + 一次性把攻击窗口压到最小。

## 小程序确认页（pages/wechat-login/index）

扫码进入时小程序码的 scene 作为 `options.scene` 传入，且微信做过一次 URL 编码，
**必须 `decodeURIComponent`**；开发者工具「编译模式」调试走普通 query，
兼容 `options.ticket`。ticket 需匹配 `^[a-f0-9]{32}$`，否则显示失败态。

四态 UI：
| state | 含义 | 操作入口 |
|---|---|---|
| `working` | 正在 wx.login + confirm | 「不是我操作的？点此取消」→ 调 cancel |
| `success` | 确认成功 | 「返回电脑继续」→ `wx.exitMiniProgram`（失败时提示手动关闭） |
| `cancelled` | 已取消 | 「返回登录页」→ `wx.reLaunch` 到 login |
| `failed` | 失败（票据无效/过期/已使用/网络异常） | 「返回登录页」 |

实现要点：
- 请求走 `utils/request.js`（`skipAuth: true`），API 地址读 `utils/config.js` 的 `BASE_URL`；
- 成功后 `wx.vibrateShort` 轻震反馈（不支持的机型静默忽略）；
- 不用 `wx.navigateBack`：扫码进入时页面栈只有本页，navigateBack 必然 fail。
- 页面已在 `app.json` 的 pages 注册，不加 tabBar。

## 网页端集成（WechatQrLogin 组件）

`apps/web/src/components/WechatQrLogin.tsx`，已挂在 `LoginPage` 登录模式表单下方
（「或」分隔线下）。集成方式：

```tsx
import { WechatQrLogin } from "@/components/WechatQrLogin";
// 直接渲染即可：
<WechatQrLogin />
```

行为：点击「微信扫码登录」→ `POST /api/auth/wechat/qr` 拿 ticket + 二维码 →
展示二维码并每 1.8 秒轮询 status → confirmed 时调用
`useAuth().loginWithToken(token, username)` 写入 localStorage（`v3_token`/`v3_username`，
与账密登录同一套存储），RequireAuth 自动跳转首页。cancelled/expired 显示提示并提供
「重新生成二维码」。组件卸载或重新生成时停止轮询；单次轮询失败（网络抖动）继续重试。

配套封装在 `apps/web/src/lib/api.ts`：`fetchWechatQr()` / `fetchWechatQrStatus(ticket)`。

## 环境变量配置

| 环境变量 | 必填 | 说明 |
|---|---|---|
| `WECHAT_APPID` | 是* | 小程序 AppID（也可放 `config.json` 的 `wechat_appid`） |
| `WECHAT_SECRET` | 是* | 小程序 AppSecret，**只读环境变量**；缺失时扫码登录接口返回 503 |
| `BOOKFINDER_SECRET` | 建议 | token 签名密钥；不设则每次启动随机生成，重启后所有用户重新登录 |
| `BOOKFINDER_MOCK_WX` | 否 | `true` 时开启 MOCK 模式：qr 返回占位二维码（SVG），confirm 跳过微信接口、任意 code 可确认。**仅用于本地联调，生产严禁开启** |
| `WECHAT_ENV_VERSION` | 否 | 小程序码指向的版本：`release`（默认）/ `trial`（体验版）/ `develop`（开发版）。正式发布前用 develop/trial 即可真机联调 |

\* 未配置时仅扫码登录相关接口 503，不影响账号密码登录与 `/api/auth/wechat` 之外的其它功能。

### 本地 MOCK 联调

```bash
cd apps/server
# Windows cmd:
set BOOKFINDER_MOCK_WX=true && set BOOKFINDER_SECRET=test-secret && uv run main.py
# 或直接 python：
# set BOOKFINDER_MOCK_WX=true && .venv\Scripts\python.exe -m uvicorn main:app --port 8000
```

curl 走通全链路：

```bash
# 1. 生成票据（MOCK 下 qr_image 为 SVG 占位图）
curl -X POST http://127.0.0.1:8000/api/auth/wechat/qr
# → {"ticket":"0c32d0d3...","qr_image":"data:image/svg+xml;base64,...","expires_in":300}

# 2. 轮询（pending）
curl "http://127.0.0.1:8000/api/auth/wechat/qr/status?ticket=<ticket>"

# 3. 模拟小程序确认（MOCK 下任意 code）
curl -X POST http://127.0.0.1:8000/api/auth/wechat/confirm \
  -H "Content-Type: application/json" \
  -d '{"ticket":"<ticket>","code":"mock_code_001"}'
# → {"ok":true,"username":"wx_mock_ope"}

# 4. 再次轮询领取 token
curl "http://127.0.0.1:8000/api/auth/wechat/qr/status?ticket=<ticket>"
# → {"status":"confirmed","username":"wx_mock_ope","token":"..."}

# 5. 用 token 访问受保护接口
curl http://127.0.0.1:8000/api/me -H "Authorization: Bearer <token>"

# 6. 同一票再轮询 → {"status":"expired"}（已被消费）；再 confirm → 409
```

## 真机发布注意事项

1. **合法域名**：小程序后台「开发管理 → 服务器域名」配置 request 合法域名
   （已备案的 HTTPS 域名）；`apps/miniprogram/utils/config.js` 的 `BASE_URL` 改为正式域名。
   开发期用「详情 → 本地设置 → 不校验合法域名」跳过。
2. **小程序码 env_version**：正式发布前把 `WECHAT_ENV_VERSION` 设为 `develop` 或 `trial`，
   开发者/体验者即可扫码打开开发版/体验版小程序完成真机验证；小程序正式发布后
   改回 `release`（或不设，默认 release）。
3. **发布顺序**：先提交小程序审核发布（`pages/wechat-login/index` 已在 app.json 注册），
   再上线生成小程序码的后端。后端生成码时已设 `check_path: false`，
   页面未上线时生成码不会报错，但扫码会打不开页面。
4. **凭据安全**：`WECHAT_SECRET` 只走环境变量，不要写进 `config.json`（启动时会主动忽略
   并告警）；本地与线上共用 AppID 时会互相顶掉 access_token，后端已做缓存 + 失效重试，
   但仍建议分开。

## 与源项目（AI消息源 v7.1）的差异

| 维度 | 源项目 v7.1 | 本项目 |
|---|---|---|
| 登录态 | httpOnly cookie session（`createSession`） | Bearer token（`auth.make_token`，30 天），轮询命中时直接返回给网页端存 localStorage |
| 浏览器绑定 | `wx_login_key` httpOnly cookie，轮询时校验 ticket 与发起浏览器配对 | **未迁移**。token 发给轮询方，拿到 ticket 的人在 5 分钟窗口内可冒领——靠 ticket 不可预测（16 字节随机）+ 一次性 + 短时效兜底。如需加强可后续加绑定 |
| 存储 | Prisma（PostgreSQL） | sqlite3（`data/app.db`），与现有用户库一致 |
| 二维码生成 | fetch 封装 | `requests` 封装（stable_token 缓存 + 40001/40014/42001 失效重试，逻辑一致） |
| 错误信封 | `{success, data/error}` | FastAPI `{detail}`，与现有接口一致 |
| 用户模型 | 独立 WechatAccount 表 + 占位邮箱 | 复用 `users` 表 openid 列（`find_user_by_openid` / `create_wechat_user`） |
| 封禁检查 | confirm 时检查 banned | 本项目无封禁概念，未实现 |
| 限流 | Redis 配额（每日上限） | 进程内滑动窗口（与 `/api/login` 同款） |
| MOCK 模式 | 无 | 新增 `BOOKFINDER_MOCK_WX`，便于无凭据本地联调 |
